# Meridian business workspace

A responsive sales, inventory, purchasing, and accounting app for a small business. The database is embedded locally for development and switches to a standard PostgreSQL server when `DATABASE_URL` is set.

## Run locally

1. Install Node.js 20.12+ and run `npm install`.
2. Copy `.env.example` to `.env` and set the admin and customer passwords before first launch. Environment variables can also be supplied by your hosting platform.
3. Run `npm run dev` and open `http://localhost:5173`.

Without environment variables, the seeded demo accounts are:

| Role | Email | Password |
| --- | --- | --- |
| Administrator | `admin@example.com` | `Admin123!` |
| Customer | `customer@example.com` | `Customer123!` |

These are sample credentials for local evaluation. Change them before exposing the app to other people. Existing passwords are stored as salted scrypt hashes and are not changed by editing environment variables after the accounts have been created.

## Production deployment

Run `npm run build`, then `npm start`. The Express server serves the built site and API from the same origin. Supply `DATABASE_URL`, `SESSION_SECRET`, `PORT`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `BUSINESS_TIMEZONE` in your host's environment. Use a TLS connection to PostgreSQL and a secure HTTPS reverse proxy. A PostgreSQL instance may be managed online now or hosted privately later; the SQL schema in `server/schema.sql` is the same in both modes. Product images currently use image URLs, so use a private object store or internal image server for a fully private deployment.

The app creates tables and default accounts on startup. Online PostgreSQL starts with an administrator and an empty catalog; the sample customer and sample products are created only for the local embedded database. The chart of accounts can be extended in the admin workspace; the core account codes used by transaction posting are documented in `server/db.js`. Local data lives in `.data/`, which is ignored by Git. Use a separate PostgreSQL database or deployment for each client's private data.

## Accounting behavior

- Opening goods debit Inventory and credit Opening equity.
- Stock purchases debit Inventory and credit Cash, Bank, or Accounts payable. Inventory uses a weighted average unit cost. Cost of goods sold is posted when goods are sold.
- Invoices debit Accounts receivable and credit Sales revenue. Confirming a cash or transfer payment debits Cash or Bank and credits Accounts receivable.
- Credit invoices have a 30 day due date. An overdue unpaid credit invoice blocks further orders for that customer until it is fully paid.
- Expenses debit the chosen expense account and credit Cash, Bank, or Accounts payable. Other income debits Cash or Bank and credits an income account.
- Posted invoices, payment methods, and delivery print records have no edit endpoint. Delivery order print dates are generated by the server for each print event.

The reporting dashboard presents lifetime figures. It does not yet provide period filters, tax accounting, returns, vendor payable settlement, or automated payment gateway verification. Bank transfers are added to bank income only after an administrator records receipt.

## AI integration

An AI assistant can read the authenticated product catalog and use the existing admin income and expense APIs after the owner authorizes it. Use the same server-side validation and admin session checks; do not give an AI client direct database credentials. No AI provider is bundled, so deployment can choose an online or private model later.
